Architecture & Self-Healing Engine

Deployment Server uses Terraform & Native Cloud CLIs to provision cloud VMs, automatically detects your stack (Docker Compose, Dockerfiles, Vite, Next.js, Python, or static HTML), builds and runs it inside a container, routes traffic through NGINX with automated .sslip.io subdomains, and conducts automated background HTTP health-checks.

Integrations

Connect external services to trigger and automate deployments.

GitHub App Webhook

Connect your GitHub App or repository webhook to trigger automatic deployments on every push or when a deployment issue is opened.

/api/webhook/github
Set this as your GitHub App webhook URL. Supported events: push, installation_repositories, issues.

Supported Triggers

  • Active issue_comment / issues — Triggers ChatOps actions like /deploy, /update, /status
  • Active push — Auto-reloads code in-place on git push in 4 seconds (zero downtime)
  • Active installation_repositories — Auto-registers new repos when added to the GitHub App

GitHub ChatOps Slash Commands

/deploy [provider] Launches deployment on specified cloud (aws, gcp, azure, do, or cheapest).
/deploy cheapest Analyzes pricing across all configured clouds and picks the lowest-cost provider automatically.
/update Fast in-place reload: pulls latest commit & restarts container on existing VM in ~4 seconds without rebuilding infrastructure.
/status Replies with live public IP, automated subdomain URL, uptime, and current health status.
